# Casefile frontend

The Casefile web app, built with Next.js 16 (App Router), React 19, TypeScript and Tailwind CSS v4. Users sign in, upload documents, and chat with them. Answers cite their sources, and clicking a citation opens the original file with the cited passage highlighted.

## Features

- Sign-up, email confirmation and sign-in against Cognito, entirely in the browser (Amplify, SRP). There is no server-side session.
- A dashboard with the chat, the saved conversations (titles generated by the backend, renameable) and the documents panel (upload, status, delete).
- Answers rendered as Markdown, with `[n]` markers linked to their citations and a collapsible list of every source the model was given.
- A PDF and image viewer (`react-pdf`) that opens a document at the cited page and highlights the passage from its bounding boxes. The open conversation and document are kept in the URL (`/?c=<id>&doc=<id>&page=<n>&passage=<chunk id>`), so views can be linked and reloaded.
- A profile page for the Cognito attributes, with usage computed from the document list.

## How it talks to the backend

The browser calls the FastAPI backend directly (`NEXT_PUBLIC_API_URL`) with `Authorization: Bearer <access token>`. All calls and the response types are in `lib/api.ts`. Original files are loaded from S3 through short-lived presigned URLs that the backend returns.

## Running locally

This is the detailed version of step 6 in the root README.

### Prerequisites

- Node.js 20 or newer, with npm.
- Floci on `http://localhost:4566` with the Cognito pool and app client from `../infrastructure`.
- The backend API on `http://127.0.0.1:8000` with `CORS_ORIGINS=http://localhost:3000`, and its worker running if you want uploads to be indexed (see `../backend/README.md`).

### 1. Settings

```bash
cp .env.example .env.local
```

| Variable | Value |
|---|---|
| `NEXT_PUBLIC_COGNITO_USER_POOL_ID` | The Terraform output `cognito_user_pool_id` |
| `NEXT_PUBLIC_COGNITO_CLIENT_ID` | The Terraform output `cognito_web_client_id` |
| `NEXT_PUBLIC_COGNITO_ENDPOINT` | `http://localhost:3000/cognito` locally; unset for real Cognito |
| `COGNITO_DEV_PROXY_TARGET` | `http://localhost.floci.io:4566` locally; unset for real Cognito |
| `NEXT_PUBLIC_API_URL` | The backend, `http://127.0.0.1:8000` |

The pool and client ids must be the same ones the backend's `.env` uses, or the backend rejects every token with 401.

Floci doesn't answer CORS preflight requests, so the browser can't call it directly. Instead it sends Cognito calls to `/cognito` on the app's own origin, and `next.config.ts` forwards them to `COGNITO_DEV_PROXY_TARGET`.

`NEXT_PUBLIC_*` values are built into the browser bundle. Restart `npm run dev` after changing them.

### 2. Install and start

```bash
npm install
npm run dev                   # http://localhost:3000, with Turbopack
```

### 3. First sign-in

Register at http://localhost:3000/register with an email, a password (at least 8 characters, with upper and lower case letters and a number) and your name. Floci doesn't send emails: the confirmation code is in the JSON list at http://localhost.floci.io:4566/_aws/ses. After confirming, you land on the dashboard.

### Production build

```bash
npm run build                 # also the type check
npm run start
```

### Troubleshooting

- Sign-in fails with a network error: Floci isn't running, or `COGNITO_DEV_PROXY_TARGET` is wrong.
- Signed in, but every list is empty and uploads fail: the backend isn't reachable at `NEXT_PUBLIC_API_URL`, its `CORS_ORIGINS` doesn't include `http://localhost:3000`, or its Cognito settings differ from yours.
- Uploaded documents stay "processing": the backend worker isn't running.
